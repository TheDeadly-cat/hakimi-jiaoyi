# 离线共享资金台（M3-1 候选）

安装候选 `0.5.0.dev3` 后，运行 `hakimi-trade`，选择 **17 离线共享资金台**。选择 1 新建示例，再选 4 生成两任务的意图；操作 ID 填 `first-cohort`，时点和任务路径留空使用示例固定值。账户本金为 10,000 USD，两任务各申请 8,000；第一笔预留 8,000，第二笔因可用资金不足整笔拒绝，剩余可用 2,000。任务配置中的独立本金 1,234 不用于共享账户。

状态页同时显示现金、持仓、预留、可用资金、权益、全局暂停、损失停机和提交流水。选择 5 显式合成结算、6 取消或 7 拒绝，输入页面所列完整意图 ID。结算使用现有研究成交模拟器，取消／拒绝释放预留；任何一项都不会提交券商订单。示例的满仓上限、零费用和时点只是固定验收输入，不是参数建议。

退出重开后选择 2 重新选择账户、3 查看状态、12 按操作 ID 查回执。提交结果不明时先查回执；系统不会自动重发。相同操作 ID 与相同请求返回原回执，相同 ID 改请求会停止。终态信号不能通过另换操作 ID 重开；取消后需新的明确机会才可再申请。恢复不会重新发布历史操作。

## 命令行

所有写入都要求唯一 `--operation-id` 和精确固定 UTC 秒 `--at`。以下命令使用新目录；已有目录不会覆盖。

```powershell
hakimi-trade shared-demo --directory .\shared-example
hakimi-trade shared-step --account .\shared-example\account --operation-id first-cohort --at 2024-11-11T14:30:00Z --task .\shared-example\workspace\tasks\shared-benchmark.json --task .\shared-example\workspace\tasks\shared-ma.json
hakimi-trade shared-show --account .\shared-example\account
hakimi-trade shared-receipt --account .\shared-example\account --operation-id first-cohort
```

`shared-show --journal` 包含封存的任务／行情／研究输入及完整回执。普通状态输出显示判断、原因和流水，不展开所有封存输入。`shared-init --config <文件>` 接受明确的合成账户 JSON；`shared-init --demo` 创建另一个固定手工信号示例，其时点为 2024-11-08 14:30 UTC、价格 101，可配合 `shared-reserve --demo` 使用。手工信号明确标为 `FIXED_SYNTHETIC_SIGNAL`，不能伪装成注册任务。

| 命令 | 附加输入与行为 |
|---|---|
| `shared-step` | 一个或多个 `--task`，按输入顺序调用五类既有注册规则，再进入同一账户风控；限合成快照和合成研究上下文 |
| `shared-reserve` | `--intents` JSON 数组或 `--demo`；固定手工信号入口 |
| `shared-settle` | `--intent-id`；当前固定时点和价格须与预留一致，再复查全局约束 |
| `shared-cancel`／`shared-reject` | `--intent-id --reason`；释放现金或卖出数量预留，记录终态 |
| `shared-mark` | `--prices` JSON 证券 ID → 原生数值；必须提供全体证券，时钟不能倒退，同一时点不能改价 |
| `shared-pause` | `--reason`；阻挡新增 BUY 和此前预留 BUY 的结算，仍允许减仓和释放 |
| `shared-resume` | `--expected-head`；要求当前流水头、当前完整价格、无预留、损失及全局仓位／现金约束均允许 |
| `shared-day-reset` | `--expected-head`；要求进入更晚 UTC 日期、当前完整价格、无预留；显式更新日损失基线，保留人工暂停 |

## 风控与恢复

一个 `account.json` 绑定不可变配置、代码及依赖身份；`ledger.sqlite3` 是追加流水。SQLite `BEGIN IMMEDIATE` 把读取、判断、预留和回执放在同一事务。跨进程先后以实际提交流水为准，同批以任务／意图输入顺序为准；不会自动缩小后一笔金额。并发调度可能改变哪一笔先提交。

统一限制包括可用现金、现金底线、总仓位、单证券占用、实际与预期成本后的组合日损失，以及全局暂停。等待结算的 BUY 也占现金及预期仓位；等待 SELL 锁定所属任务的数量，不提前释放现金或净额抵消 BUY。现有策略风控仍负责生成基础数量，共享准入整笔允许或拒绝，不再缩量。持仓按任务归属记录，可管理任务使用稳定任务族 ID；旧不可变任务按其语义身份归属。策略版本身份和输入摘要保存在流水中。

每日基线采用 UTC 日期，仅显式 `shared-day-reset` 更新。损失停机不会因价格回升、跨日或重开自动解除。人工恢复不修改历史判断，也不重试已拒绝信号。暂停和恢复均有流水记录。

恢复从流水重建现金、持仓和预留，检查序号、哈希链、原判断、状态摘要及确定性转移。校验会重算隔离内存中的合成转移，不写回、不重新发布、不访问外部账户。提交前进程崩溃回滚；提交后、返回前崩溃则原回执存在。操作回执查询明确区分 `COMMITTED` 和 `NOT_RECORDED`。部分准备目录及失败日志保留，已有目录不会用作新账户。

关闭程序后可复制整个示例／工作区到新目录，原件保留。相同候选读取和继续操作不依赖原绝对路径。写入要求原账户的代码及依赖身份；升级时须另行迁移验收，不自动改签账户。流水校验用于本机一致性检查，不是防止能改写所有本地文件的管理员伪造的外部认证。

## 当前范围

交付共享合成账户和固定时点意图运行；不把各自本金的回测收益相加。五类规则复用现有双均线、买入持有、公告排期过滤、公告后价格确认和已核准指引条件。任务步骤仅在合法评分会话开盘运行，使用此前可用日线；固定开盘保护性减仓复用现有风控。完整逐根 OHLC 保护和增量监控仍是后续工作。

仅 USD、合成证券、现货多头、1 倍杠杆、碎股与既有固定费用／滑点近似。部分成交不入共享账；失败则整笔拒绝并释放。没有真实账户、保证金、做空、公司行为记账、券商执行或后台监控。原独立任务运行、历史报告和正式 Release 保留各自身份。M1、M2-1、R1／R2／R3 和 PR #23 的两项 P2 均保持关闭，Unknown／T3 保持暂缓。

## dev2 时间保护与旧账户

dev2 的新账户采用 v2 时钟规则：只有显式 `shared-mark` 更新全体价格才能推进账户时点。预留、结算、取消、拒绝、暂停、恢复及新日基线都使用页面当前固定时点；错误的较晚时点在发布流水前拒绝，不能让其他预留失效。不确定当前时点先用 `shared-show` 查看。合法更新价格后，旧预留的过期拒绝／释放保持原行为。

dev1 的 v1 账户在 dev2 中仅只读，按原语义验证原回执，保留原字节和原判断，不给旧账户改签或自动更新时钟。新操作创建独立 dev2 合成账户；旧 dev1 包及其原验收范围保留。

## dev3 单 symbol 配置与历史记录

新建账户的证券配置必须让每个 symbol 只对应一个证券 ID，比较时忽略大小写。两个 ID 的 `TEST`／`TEST` 或 `TEST`／`test` 在账户及流水发布前拒绝，避免利用别名绕过单证券上限；不同 symbol 仍分别计入单证券上限，并共同受现金及总仓位限制。

dev3 保留 v2 时钟规则和回执格式。原 dev2 含别名的账户按原语义只读重建，页面明确显示只读，新写入被阻挡，原判断及原字节保留。旧账户仍要求原代码及依赖身份才能写入，不自动迁移或改签；升级后的新操作使用当前候选的新账户。原 dev1／dev2 安装包、失败和已验范围均保留。
