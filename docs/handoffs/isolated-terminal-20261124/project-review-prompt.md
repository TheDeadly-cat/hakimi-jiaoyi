# 项目投入与产出复盘提示词

请按管理层能据此决定是否继续投钱的标准，复盘当前项目从立项到今天的投入和产出。说人话，先给结论。用现有记录做只读核对，写明统计截止时间；这次复盘自己的消耗另列。优先看已有证据，避免为了写报告重跑训练或整套测试。

1. 当初要解决用户的什么问题？今天用户实际能完成什么？指出有证据的成果、没验收的承诺，以及过程中是谁提出了哪些范围变化。缺记录就写未知。
2. 实际花了多少？核对可访问的主聊天、分支、并行任务、自动化和项目账单。按独立模型响应去重，排除分支继承的累计值。分别列总 token、其中的缓存输入、实际扣费、日历跨度、去掉并行重叠后的运行时间，以及有记录的人工时间。没有账单就把实际费用留空，说明覆盖哪些时期和项目。
3. 投入去了哪里？按基础建设、核心业务验证、界面与功能、明确返工、测试审查、等待值守、协调及无法拆分的工作列一张表，每项给用量、时间、交付物和数据依据。标明实数和估算，只对可核对的范围算占比。
4. 哪些投入值得，哪些是失误？各举具体例子。测试找出了什么会影响用户的错？哪些重跑源于测试本身、重复执行或需求理解错误？训练、构建等任务分别花了多少机器运行时间和模型协助时间？有现成记录就量化，别把抽样比例推到整个项目。
5. 别人完成同等范围通常需要多少？优先找同规模、同验收标准的公开案例。缺乏可比数字就直说，再用本项目一次真实执行说明哪些工作本可更省。
6. 最后给“继续投入、缩小范围、暂停”中的一个建议。列出该保留、该停止的工作，以及下一笔预算要换来什么可验收结果、何时停止。正文一页，附可追溯的依据。共享版去掉账户、私聊编号、密钥和本机路径。
