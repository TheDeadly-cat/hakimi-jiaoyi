# 富途官方模拟适配器：首个订单周期候选

适配器在 `tools/futu_simulation_adapter.py`，独立于已安装研究包。复用 `execution_state_lab.py` 的持久化意图、提交领取、累计记账、撤单和重启对账；使用单独的数据库应用标识、模式和查询范围。原本地实验CLI仍只接受 `LOCAL_SIMULATOR`，不能借本地模拟端发送官方订单。

本候选的[代码检查、真实只读预检和版本身份](research-evidence/futu-simulation-adapter-20260913/validation.json)分别记录。**真实官方下单、成交/撤单周期及费用对账尚未完成。**当前命令行仅有只读预检，模块中的订单方法必须由获得单独授权的调用者使用。

## 首个周期的明确边界

- 固定本机 `127.0.0.1:11111`、`futu-api==10.7.6708`、实际识别的美股 `STOCK_AND_OPTION` 模拟账户ID。所有交易查询和写调用显式传入 `SIMULATE` 与该ID，不使用账户下标。
- 首个周期限定AMD正股、1整股、至少1美元的0.01美元整档限价、DAY、RTH、零价格自动调整。每次提交前重新核对实际证券ID、NASDAQ、股数单位、价格步长、常规时段开放状态及现金可买/现有持仓可卖上限。融资购买力和可卖空数量不作可用资金/持仓。
- 授权声明绑定账户、意图、完整订单载荷摘要、最长24小时到期时间及账户独占操作范围。该声明是维护者授权的程序输入，不是哈希自动产生的授权。当前没有为真实账户生成模拟下单授权。
- 相同本机账户使用进程锁和持久的数据库身份登记。复制数据库到另一路径不能变成新的执行权威；跨机器/其他客户端独占仍须由维护者保证，不能称为跨机器锁。
- 新数据库必须使用与账户绑定的、60秒内两轮一致的空订单查询作初始依据，不能从任意金额自动初始化。既有持仓完整保留为初始状态；其他证券没有因此获得交易权限或虚构的价格规则。

## 查询、回调与未知结果

订单、历史订单、原币美元现金和持仓按两轮查询比对，要求投影一致、没有排队回调且在5秒内完成。这是有边界的一致性检查，**不是券商原子快照**。历史查询明确起点，遇到分页形状、过大结果、当前/历史冲突、字段缺失、状态变化或未知订单则停止推进。

SDK回调先排队，由状态机所属线程处理；先持久化可能提交，再调用SDK。同步响应前的回调先记录。响应丢失不会换意图或重新发送；测试用主动丢弃同步响应也会明确标为客户端故障注入，不能称为供应商真实网络故障。

固定SDK的订单DataFrame不含账户ID，实际编号来自protobuf的交易消息头。适配器分别保留消息头和SDK解码订单，验证账户、环境与市场，不从配置补造缺失的消息头。缺失或错误消息头、解码失败和订单市场冲突会停止推进。依据为已安装SDK源码和官方[订单推送协议](https://openapi.futunn.com/futu-api-doc/en/trade/update-order.html)。

提交与撤单在查询结束、持久化领取前，以及实际SDK调用前分别重验授权有效期。单次调用复制授权内容，调用方中途修改原对象不能延长当前操作。若授权在领取后过期，记录本地未发送原因，保留已提交的未知状态与停止标记，不伪装成券商拒单或自动重新领取。

SDK原始订单状态和累计股数立即保留，缺失费用与逐笔成交证据保持 `None`。这些订单不会被当成已经完成记账，账户金额也不会把未核实变动伪装成精确余额。可对已识别的己方订单申请撤销，撤销响应不等于终态；撤单不依赖市场仍开盘。

富途官方[模拟交易说明](https://openapi.futunn.com/futu-api-doc/en/qa/trade.html)明确：模拟成交查询/推送、订单费用、现金流水不可用。若以后从实际模拟界面或导出取得维护者核对的账单，`admit_statement`要求实际原件字节、相符摘要、订单ID与累计数量，并将原件留在本地数据库，再复用既有记账和余额/持仓对账。原件摘要只证明身份，不认证人类意见或文件真实性；当前没有实际账单，不自动填零。

## 已遇到的真实接口差异

首轮预检因资金返回 `currency=N/A` 被拒绝，原失败保留。官方[资金字段定义](https://openapi.futunn.com/futu-api-doc/en/trade/get-funds.html)说明展示币种参数仅适用于特定账户，而 `us_cash`独立表示原币USD现金。代码据此使用 `us_cash`；未用展示币种或含融资的 `power`猜测现金。修正后实际两轮账户读取和AMD证券规则查询成功，当前市场返回闭市状态。完整原件、余额、持仓及账号留在本机。

价格和最大可买卖规则分别依据[下单参数](https://openapi.futunn.com/futu-api-doc/en/trade/place-order.html)及[数量查询](https://openapi.futunn.com/futu-api-doc/en/trade/get-max-trd-qtys.html)，实际下单时还须重新读取。模拟手续费与结算最终行为仍需实际订单及独立原件，不由文档费率或研究0.08%假设代替。

## 运行与验收

私有profile必须明确 `schema_version=futu-simulation-binding-v1`、`account_id`、`market=US`、`symbol=US.AMD`、`host=127.0.0.1`、`port=11111`、`history_start`。账号只从已核对的本地发现结果填写，不放在聊天或GitHub。输出目录必须是新的私有目录。

```text
python tools/futu_simulation_adapter.py --profile <private-profile.json> --output-dir <new-private-directory>
```

可选 `--capacity-price 1.00`仅查询该限价下1股的现金购买容量。真实运行通过现有 `observation_job.execute` 放入私有Windows Job，限制180秒、输出128KiB、清理5秒；SDK日志仅重定向到子进程私有目录。当前适配器没有修改桌面启动器、用户OpenD设置或正在运行的观察bundle。

针对性测试使用明确标识的SDK夹具及真实SQLite，覆盖账户/环境、授权载荷、回调先到、结果未知与重启、重复意图、费用缺失、账单原件身份、撤单竞态、非原子查询冲突、余额规则及本机重复权威。它们是软件证据，不能充当官方模拟成交记录。

`tests/sdk_contracts`另用固定的真实SDK解码合成protobuf，测试进程禁止网络连接；CI在独立虚拟环境安装`requirements.futu-sdk.lock`，不改变研究包依赖。历史验证源码的换行差异见[勘误](research-evidence/futu-simulation-adapter-20260913/source-provenance-erratum.json)；原回执不改写，新验收从Git导出的文件执行并记录逐文件摘要。
