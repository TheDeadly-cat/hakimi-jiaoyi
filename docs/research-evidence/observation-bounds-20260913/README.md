# T5 启动器有界执行：候选修复，未激活

`observation_job.py` 的旧 `capture_output=True` 会先无限缓存输出，再由调用方检查stdout大小；无整体期限的等待还可能被仍持有管道的后代延长。[修复前有限进程探针](before-probe.json)实际捕获了stdout和stderr各5 MiB，并在直接命令结束边界之后继续等待持有管道的后代约2秒。所有探针均有限、自行结束，没有连接冻结观察部署或外部行情；不把它们描述为已经发生的生产挂死。

## 改动与验证范围

固定观察命令先经过 `-I -S` 隔离引导进程。父进程将引导进程放入匿名、不可继承句柄且禁止breakaway的Windows作业对象后，才通过单字节管道放行真正命令。若归属失败，只结束尚未放行的自建引导进程；不退回无所有权的执行方式。真实命令使用无窗口启动，研究包、原包装器、计划及交易权限没有改变。

作业对象让常规CreateProcess后代保持同一归属；采用[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)的kill-on-close行为，外层启动器被终止时也结束其作业。该边界针对已固定的Python/subprocess调用链，不宣称追踪由外部服务或WMI另行创建的进程，也不通过端口或任意PID清理程序。

子进程链最多运行300秒，清理等待最多5秒；stdout和stderr同时读取，共同最多保留4 MiB。超限之后停止保留额外内容，继续排空直到结束或清理期限；回执记录已见/已留字节、摘要、截断和失败原因。退出0但仍有后代进程也报告失败，并清理该作业，不能直接升为健康结果。

首轮22项测试出现一次临时目录仍占用的清理错误；补上真正命令的无窗口标志后仍出现同样错误，两个失败记录均保留。修复继续落实到退出证明：终止前保留作业内成员的只读等待句柄，并核对句柄仍属于本作业；终止后在同一清理预算内等待进程对象完成退出、作业无活动进程及输出读线程结束。成员句柄没有终止权限，实际终止通过作业执行。该处理对应[Windows终止是异步操作、需等待进程退出](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)的语义，不用忽略目录错误或增加任意sleep掩盖失败。

最终24项针对性测试通过，0失败/错误/跳过；完整仓库配套测试132项通过，包含24项，不相加。覆盖正常输出/退出码、超时、流式合并输出上限、乱码拒绝、后代残留与真实存活检查、父进程硬退出后的文件锁释放、归属失败不启动观察器、其他测试进程不受影响、跨进程重复调用、真实loopback连接拒绝、结束回执及下一周期恢复。各测试使用自建临时目录和有限子进程；loopback拒绝由本测试保留但不监听的随机端口实现，不访问券商或行情地址。

已运行准备脚本默认预览，并实际构造ScheduledTasks设置对象：`ExecutionTimeLimit=PT10M`，`MultipleInstances=IgnoreNew`；未注册任务。OS期限留出启动器自身异常退出的余量；正常子进程路径优先使用300秒期限。v2启动/结束回执记录本次边界和工具身份，旧回执及旧冻结数据不改写。详细本地核验摘要见[validation.json](validation.json)。
