# 券商候选的离线计划合同

当前同窗候选能保存配置、检查研究关联和形成未发送意图，但没有实际券商执行链。本次补上一个供后续服务使用的纯离线计划合同：把原候选/意图、保存研究、账户与标的、程序/SDK/适配能力、模式和停止修订、金额及调用预算绑定成同一份不可变计划。它尚未接入服务或界面，不构成 T29/T30 完成。

## 身份与兼容

原策略保存的是源码文件摘要映射和规则指纹；不能假设其读取合同含有核心引擎的 `source_hash`。现有 `resolve_execution_research` 默认四字段结构和值保持不变；新增显式 `include_recorded_source=True` 才提供从已验证保存记录读取的独立源码与分类信息。旧候选摘要不变，缺失身份直接拒绝，不读取今日源码给旧报告补签。

计划逐项核对原报告、任务、输入、引擎和完整源码映射；核心引擎继续使用其原内容摘要。合成/QA 资料固定为 `SYNTHETIC_OFFLINE_ONLY`、`external_research_eligible=false`，普通缺证状态清空或重新封存计划都不能提升资格。缺失分类为 UNKNOWN，保存的认证声明也须另有外部准入证明。

官方模拟与 REAL 候选使用不同合同和账户范围。新计划不重置原意图的全局提交认领；停止/恢复修订变化会使旧计划失效。费用缺失不补零，卖出要求所属持仓证据，UNKNOWN 只查原订单身份。所有外部连接、查询、提交、取消及解锁权限仍为 false。

## 验证与仍缺的实现

25 项直接检查通过；新 TEMP 接线用例走实际保存结果读取 → 原候选保存 → 显式读取保存源码 → 计划校验。用例报告是明确 SYNTHETIC_TEST / not_computed 的手工封存夹具，0 runner，不能当作真实研究或市场证据。旧研究与候选字节、mtime 不变；独立内存比较确认 native/core 默认输出与旧实现字节一致。

新测试已登记终端门禁，Windows 包收录映射增加精确断言。完整终端门禁489/489通过（0跳过、214.376秒），直接打包检查11/11通过（4.896秒），六个相关输入文件哈希前后稳定；结果见 `integration-summary.json` 和随附日志。当前 r2 包不含此模块，下一候选还须验证包内显式导入及实际来源。

后续仍需可信的包加载器与计划服务、独立执行账本中的持久认领和共享占用、原子停止/认领/派发屏障、有界 worker，以及针对当前候选的实际适配器。执行器必须独立强制研究资格与明确授权；计划校验通过不能代替其中任何一步。没有执行 SDK、OpenD、外部券商、真实资金或历史暂停事项。
