# T5：冻结程序隔离故障演练与退出竞态修复

本轮实际调用了复制到仓库外的冻结 Python、包装器、驱动和采集器。安装源码与依赖验证均通过；复制的 3,710 个文件中，仅新副本的 `forward/deployment-plans.json` 改为指向副本内的计划路径。原计划、工具、安装环境及原部署受保护文件逐项核对字节未变。旧周期数据没有复制，因此副本里的历史缺失不能算作生产缺口。

[fault-drill.json](fault-drill.json)保存当前公开投影、原回执摘要和验证范围。原始失败记录、机器路径、完整日志和临时安装副本保留在本地，未加入仓库。旧启动器验收字节与这次修复后的启动器摘要分别记录。

## 实际结果

| 演练 | 观察到的结果 |
|---|---|
| 本地代理拒绝网络 | 真正采集器发出一次 CONNECT，独占 loopback 代理返回 503，从未转发外部请求；没有形成输入快照或观察记录 |
| 同一实际小时重试 | 不完整小时目录仍保留，原驱动拒绝重取并混合数据；启动器和冻结包装器的锁均可重新取得 |
| 持有采集连接时重复调用 | 第二个启动器返回 `DUPLICATE_IN_FLIGHT`，没有产生第二次采集连接或有效结果声明 |
| 强制终止自建启动器 | 仅使用该启动器原有 Popen 句柄；终止前观察到的 10 个后代进程句柄在约 0.046 秒内全部转为退出状态 |
| 终止后重试 | 保留启动而未结束的回执，重试识别该未完成任务并释放锁；同一不完整小时仍拒绝，未改写为成功 |

所有调用均为隔离副本的实际 `MANUAL` 调用；没有伪造整点、调度事件或信号时间。强制终止演练时的进程祖先快照仅用于保留只读等待句柄，未用发现的 PID 或端口终止其他进程。

## 首轮暴露的竞态

网络拒绝首轮没有通过预期分类断言：预期 `CHILD_FAILED`，实际为 `CHILD_LEFTOVER_DESCENDANTS`，但清理已确认且结果无效。该失败原件保留。

随后对同一已失败小时进行八次有限、无重取的诊断调用，复现一次：作业首次计数为 1；取得成员句柄时该句柄已退出，零等待返回 0；再查作业已为 0。旧实现仍依据首次计数报告残留。这里只能确认退出竞态，未能取得已退出进程的镜像名称，不推断具体进程类型。另三次采集器单项拒绝探针没有复现，单项结果不替代完整链路证据。

修复在取得成员句柄后，立即复核句柄已退出且作业已空，满足两项时保留正常退出分类；仍有活跃成员时继续失败、终止本次作业并等待清理。没有增加宽限 sleep、改变超时和输出上限，或放松实际残留后代的拒绝条件。

针对这一竞态的回归在修复前失败，修复后包含它的 25 项启动器测试通过；按 CI 的仓库导入路径执行的 133 项配套测试通过，包含前述 25 项。首次回归夹具有 Windows 换行预期错误；首次配套测试调用漏设仓库导入路径，85 项加载/测试记录中有 9 项导入错误。两类调用错误与有效的修复前失败均保留，不计为成功证据。更新后的实际冻结链路同小时重试确认 `CHILD_FAILED`、进程边界 `EXITED`、清理完成；该小时仍没有有效观察。
