## 样本与口径

前三次分别启动新的 Python 子进程；测量前检查研究运行模块尚未导入。随后另启一个进程，先显式导入同一组研究运行模块，再顺序执行三次完整流程；没有丢弃任何完整流程样本作为预热。原 `tools/profile_research_pipeline.py` 未修改，校验、序列化、保存和完整规范重放全部保留，没有插桩。

这里的“冷”仅指**新 Python 进程中的模块导入**；未清空操作系统文件缓存。这里的“暖”仅指同一进程中已导入的模块；每次仍重新读取、验证快照并使用原 Runner。不能把两组的差异解释为新增缓存或改进引擎后的收益。

测量前等待本轮连续研究、策略诊断及其重放、发布核验进程全部结束。测量前后的进程库存只见本测量的 Python 启动器与编排进程；这不代表普通桌面、操作系统或硬件负载已隔离。完整库存与实际开始/结束时间保存在[汇总](summary.json)、[启动记录](run-started.json)和每个样本文件中。

## 复核命令

`tools/repeat_pipeline_profile.py` 只新增测量编排，使用相同受验收 0.2.1 安装、清除子进程 `PYTHONPATH`/`PYTHONHOME` 并设置 UTF-8。`freeze` 固定计划，`run` 执行六个样本。现有完成结果会被保留；部分失败样本不会被偷偷覆盖或重新抽样。

```powershell
$researchPython = '<受验收 0.2.1 虚拟环境>\Scripts\python.exe'
& $researchPython -B tools/repeat_pipeline_profile.py freeze --root . --public docs/research-evidence/performance-repeat-20260906
& $researchPython -B tools/repeat_pipeline_profile.py run --root . --public docs/research-evidence/performance-repeat-20260906 --research-load-status OTHER_RESEARCH_PROCESSES_CONFIRMED_TERMINAL
```

第二条命令的负载状态须先由实际运行状态确认；若仍有并行研究负载，使用 `PARALLEL_RESEARCH_LOAD_NOT_ISOLATED`，并保留该限制。本次使用前者，普通系统负载未隔离的限制始终有效。
