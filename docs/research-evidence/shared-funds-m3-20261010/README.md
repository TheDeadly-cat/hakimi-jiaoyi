## 功能验收

| 工作项 | 实现与已验证范围 |
|---|---|
| 共享账户 | 一个不可变配置及追加 SQLite 流水，统一现金、持仓、预留、可用资金、权益和归属；读后文件摘要保持 |
| 统一意图 | 五类既有注册策略的实际固定时点输出进入共用风控；任务独立本金不参与共享账户计算；手工合成信号另标来源 |
| 固定竞争 | 用户选择按提交流水顺序整笔通过或拒绝；同批按输入顺序。10,000 账户收到两笔 8,000：仅一笔预留，第二笔整笔拒绝，可用 2,000；并发胜者可因调度不同 |
| 预留与恢复 | 操作 ID 去重、规则／时点信号去重；取消／拒绝释放，终态不重开；真实两进程竞争与提交前／后中断分别验证 0／1 份已提交回执，不自动重发 |
| 全局约束 | 总仓位、单证券占用、现金底线、含预留成本的预期权益与组合日损失；SELL 锁定归属数量，不能取用其他策略持仓；人工暂停和有条件恢复留流水 |
| 产品入口 | `shared-*` 冷进程命令和菜单 17；实际创建、生成意图、结算、取消、损失停机／跨日基线／恢复、回执查询、退出重开及目录迁移通过 |

[安装后实际流程](installed-shared-funds.json)记录全部五类规则、实际进程竞争、COMMIT 前退出 74／后退出 75、预留与条件恢复。两个进程的实际流水为 2，一笔 RESERVED、一笔 REJECTED；不存在两笔都使用独立 10,000 本金的情况。可管理任务按任务族保留持仓，版本变化不丢失归属；其他边界由同一已安装包的根测试覆盖。
