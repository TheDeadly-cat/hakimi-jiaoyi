## R3：显式 GET 重试等待已完成开发修复

HTTP 429、502、503、504 的单一有效 `Retry-After` 支持非负秒数和 HTTP 日期；秒数从收到错误响应后计时，日期转换为等待时长后使用单调时钟等待。该字段的两种形式遵循 [RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)。

- 缺失、非法、多重或已过期的值采用 1 秒、2 秒固定退避；有效零秒允许立即进入下一次有预算的尝试。
- 超长有效秒数和超出剩余总时间的等待均停止，不截短等待后提前重试。等待计入原 150 秒总期限，默认仍只有一次请求，最多 3 次尝试／170 次共享请求。
- 证书错误、非法来源及非重试状态不重试。等待失败保留原失败阶段和类型；等待中的阶段单独标记 `RETRY_WAIT`，外层超时不会被误写成仍在接收 HTTP 头。
- 日志不记录头值、URL、正文或凭据。原拥有者进程继续负责硬期限；未更改部署、调度、旧 O1 或订单侧逻辑。
