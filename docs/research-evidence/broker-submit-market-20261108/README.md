# 原发送流程的必需观察条件

此前 profile 声明了行情查询预算，但原 submit 不消费已经留存的行情事实。本批在原协调器与原账本中加入 v3 必需观察条件：资金认领、提交 ACTION 和每次实际写入都必须使用同一个、仍在有效期内的观察包。资料不全、状态不符、期限届满或停止后，不能继续新发送；已经产生的原记录仍按原操作 ID 只读找回。

观察包来自原账本的 **两次握手与四类查询**：quote/trade 初始化、全局状态、证券资料、快照、目标证券市场状态。它绑定原 ACTION、事实 ID、请求与响应哈希、账户与原意图范围、证券以及已接受的会话。预置会话 ID、调用者自封字典或旧版 permit 不能代替这条引用链。

## 具体检查

- 目标必须是精确 market/code 对应的普通股票；登录、退市、停牌与股票状态使用明确存在的字段。静态/快照每手股数必须正且一致，观察价格必须正。缺失值不补成可用值。
- 目标状态采用 **3223 / Qot_GetMarketState** 的返回值，而非 Nasdaq 全局状态。固定观察规则只接受美股股票的 `AFTERNOON=5`。官方 [目标市场状态接口](https://openapi.futunn.com/futu-api-doc/quote/get-market-state.html) 和 [市场状态说明 Q14](https://openapi.futunn.com/futu-api-doc/qa/quote.html)支持该含义；本地锁定 10.7.6708 wheel 的协议号及枚举值也已静态核对。当前网页版本不替代锁定 OpenD 的兼容验收。
- 有效期由四个**原查询 ACTION 的开始时间**和明确的最大观察年龄决定，最多 30 秒；在截止瞬间即拒绝新发送。晚收到或重新投影原响应不能重新开始计时。该窗口是观察策略，不是行情来源更新时间或新鲜度证明。
- CLAIM/ACTION 在原 journal 事务中重新核对事实；短写屏障只校验不可变观察包、当前会话、期限和停止状态，不在 local/account 屏障中重新打开 journal 或等待网络。
- 握手的 AES/key/iv 和自由文本消息留在原私有响应帧。typed facts 只保存身份/状态白名单和原帧哈希；新握手事实不会将这些秘密材料复制到 journal 的结构化事实。

## 原记录与资金边界

v2 默认 profile、11 类协议目录和事实字节合同保留；v3 显式使用 12 类协议及独立 permit 版本。原 journal 路径、元 schema、账户和原意图去重键不变，新代码按原版本回放历史事件，不迁移或改写旧记录。跨 v2/v3 切换不能让同一原意图重新认领资金。本说明不宣称旧 r7 程序能够解释新增 v3 事件。

准备观察包不创建账本事件。重开由 `read_submit_observation()` 从已验证的原 ACTION 恢复原包，使用原事件时间，不重新查询、编码请求或刷新期限。新发送仍须通过当前期限检查；时钟回退不会复活已经观察到过期的条件。

原现金、owner 持仓和费用预留检查继续执行。明确证明未尝试写入的 `NOT_DISPATCHED` 可以按原合同释放本地预留；部分发送或未确认的记录仍保持 UNKNOWN 与相应占款，不能用进程关闭推断成功或无费用。

这是一项**必需观察条件**，不是完整交易准入。行情权限、来源新鲜度、币种与合法价量规则、可预留资金及持仓归属的真实来源、费用证明、生产授权装配和 OpenD 兼容仍需完成。独立实际报文试验也使用虚构数值、独立合成现金及自持本机测试服务，不连接券商账户。

本批为 [PR #28](https://github.com/TheDeadly-cat/hakimi-jiaoyi/pull/28) 后续源码。已公开的 [r7 研究与本地演练试用候选](https://github.com/TheDeadly-cat/hakimi-jiaoyi/releases/tag/v0.7.0.dev3-r7)保持原包身份；本批代码未打入 r7，不替代原生、独立 Windows 或三人试用验收。

## 验证结果与原件范围

- 一次[完整 terminal 检查](full-terminal.json) **977/977 通过**，零失败、错误或跳过，耗时 361.637 秒。独立环境实际安装当前工作树，16 个改动输入前后哈希一致；保留[环境核对](full-terminal-preflight.json)与[原日志](logs/full-terminal.log)。
- [实际 protobuf 检查](actual-protobuf-summary.json) **4/4 通过**：原锁定 12 类协议、原 worker/supervisor、原 journal/transport 和自持动态本机端口共同运行。测试段 360.336 秒，包含收尾核对的 controller 为 365.172 秒，外层 383.330 秒；这三个计时范围分别记录。
- [四个案例](actual-case-index.json)包括完整六项观察后原 2202 ACK、目标状态不符、观察过期但 permit 仍在未来，以及提前乱序 INPUT。正例关闭后按原九个操作 ID 找回，零新连接和发送，原数据库及请求注册文件字节不变。ACK 只表示请求确认，不能当作成交或费用终局。
- 状态不符和过期案例都保留独立虚构现金快照，但没有 CLAIM、提交 ACTION 或 2202。乱序案例只留下两次握手，没有查询或现金快照。过期和乱序的原 worker `UNKNOWN / exit 1` 保留；测试通过表示阻断符合预期，不改写进程结果。
- [独立只读复核](independent-review.json)逐项核对原帧、peer 字节、六项引用链和原账本，未发现审查范围内的阻断问题。定向检查和单正例诊断与上述完整检查重叠，不累加为独立覆盖。

[首次实际尝试](retained-attempts.json)的失败原件保留：四个查询请求集中编码、逐次验证绑定，超过测试的 15 秒消息等待。修复只让测试装配在前一原 ACTION 完成后绑定固定的下一个请求。没有跳过字节验证、增加产品窗口或隐藏重试。原产品 RPC 15 秒、清理 5 秒和观察窗口上限 30 秒不变。实际探针的 worker wall 60 秒、READY 30 秒等预算是独立测试边界；正例首 worker 耗时 56.566 秒，不代表生产启动性能验收。

仓库保留紧凑摘要、实际请求/响应字节、worker IO 次序、原件索引、最终探针脚本和日志。完整原 SQLite 与加载清单仍在外部证据目录，案例 `retained-artifact-index.json` 明确标记该范围。这里只核对 r7 manifest、实际加载闭包和当前源码，**不是整包重新验收**。独立复核可重算的 r2+r3 并集为 269 个包路径和 51 个当前源码路径；[原交接摘要](original-actual-handoff-summary.json)原样保存，其另一个加载计数口径不用于扩大验证范围。文件字节清单见 [SHA256SUMS.json](SHA256SUMS.json)。
