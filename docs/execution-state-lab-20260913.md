# T6：独立的本地持久化执行实验

新增 `tools/execution_state_lab.py`，完成无凭据的SQLite订单状态、提交去重、结果未知、撤单竞态、累计成交及重启对账实验。该工具独立于 `hakimi_research` 安装包，不读取行情、不生成交易策略、不实现价格撮合，也不连接券商。命令入口只驱动本地SQLite模拟端，并阻止出站Python网络访问；研究包的paper/live/order权限保持原值。

## 可运行入口

在Python 3.11及以上环境运行，不需要第三方依赖：

```powershell
python -X utf8 -I -B tools/execution_state_lab.py demo --output-dir artifacts/execution-lab-example
```

输出目录必须是新目录。包含 `client.sqlite`、`simulated-venue.sqlite` 和 `result.json`。同一路径再次运行会拒绝，不覆盖既有状态。两份数据库分别代表客户端和模拟端；模拟端故意接受重复client_id并保留多条订单，所以客户端重复发送不会被模拟端的去重掩盖。全程使用虚构 `TEST` 标的与明确的模拟成交数值。

示例先保存提交尝试，再让模拟端接受订单但丢失回包；客户端关闭并重开后仍只有一次提交。对账恢复订单ID，处理部分成交、撤单响应和随后完成的全部成交。最终客户端持有10股TEST、现金901.2，来自1000起始模拟现金减去98成交额和0.8费用，属于账务算术结果，没有市场收益含义。[实际示例输出](research-evidence/execution-state-lab-20260913/example-result.json)及[实现/测试/关闭后数据库核对](research-evidence/execution-state-lab-20260913/validation.json)绑定干净提交 `88e9c392b4233dffd658674a83a05b6fbb6086b7`，不借用其他wheel的结果。

## 关键行为

- **先持久化再提交。** `PREPARED → SUBMIT_UNKNOWN` 与尝试ID在SQLite事务中提交后，调用方才取得提交指令。一个权威数据库内，同一稳定意图ID最多尝试提交一次；即使崩溃发生在发出请求之前，也不会把查询不到订单解释成已拒绝并自动重发。相同意图ID和规范化条件幂等，不同条件拒绝。
- **重启重新对账。** 新进程不会继承旧进程的可提交状态。完整订单、现金、持仓快照须匹配本次查询标识、当前本地修订及5秒有效期；查询期间发生更新时旧快照不能继续授权。只有未成交订单列表、不明订单、重复关联、缺失提交结果或余额不符都不能放行新增风险。请求失效可以重新查询；持久化的风险停止状态需在对账后明确恢复。
- **累计成交只记增量。** 金额使用十进制字符串，数量使用整数股。重复来源回执不重复记账；落后的累计数量保留为过期观察，同数量不同累计金额等冲突会停止新增风险。额外费用计入一次，出现负模拟余额时保留已报告的成交与费用并停止风险，不能隐藏实际观察使余额看起来正常。
- **撤单响应不是终态。** 保存针对确切订单ID的撤单尝试；响应未知时不重发。接受撤单响应后仍保留订单与预留，直到取得最终状态。成交可以在撤单期间完成；迟到的部分成交回调不能重新打开已关闭订单。若新拉取的完整快照仍把该订单报告为开放，停止而不是假装已消除敞口。
- **预留与风险停止。** 开放买单预留未成交数量的限价金额和剩余费用缓冲，卖单预留剩余股份；拒绝超额买入、超额卖出和做空。持久化停止阻止新买入，仍允许对账后减少已有持仓及撤单。每次提交前再次检查当前修订、预留和未知结果。

数据库使用显式事务、WAL和FULL同步。结构、种子与应用标识一起提交；初始化中断不能留下被识别为完整实验数据库的半成品。打开既有文件前只读核查应用标识、版本和SQLite完整性；不接管其他数据库。异常对账使用保存点回滚整个批次，同时另行保存停止原因和被拒绝证据摘要，避免丢弃首次失败信息。

## 验证与适用范围

25项针对性检查覆盖真实SQLite和真实子进程退出：模拟端已提交但客户端未收到确认、创建数据库时中断、同意图并发写入、响应丢失、部分成交与迟到费用、撤单未知/拒绝/成交竞态、异常和过期快照、双向资金/股份预留及风险停止。首轮18项检查因测试夹具未关闭非实验SQLite连接而产生1个清理错误；显式关闭该连接后通过，失败日志保留。最终远端检查与可重跑示例各按实际提交和实现摘要记录。

这里的整股、美元、显式限价、价格步长、费用缓冲、8位小数金额和5秒查询有效期都是本地实验规则，不是已确认的券商规则。一个数据库对应一个执行权威；复制数据库并运行多个独立副本，不会产生跨副本的共同执行锁。没有跨账户协调、入金出金、公司行为记账、官方适配器、真实撤改单传输或后台执行服务。模拟成交由测试明确输入，不按真实盘口生成。

现有旧研究演练模块依赖研究账户/订单合同；本实验没有把该归档链路重新打开，也没有另写股票回测/撮合引擎。后续连接官方模拟盘前，还须确认产品与地区、API账户和数据权限、数量及价格规则、费用完整性、账户的单一执行权，并实现独立适配器与规范化来源。
