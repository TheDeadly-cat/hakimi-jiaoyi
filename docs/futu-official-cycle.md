# 一次官方模拟订单验收

入口为 `tools/futu_simulation_cycle.py`，复用现有适配器和SQLite状态机，不进入研究wheel或桌面启动流程。当前仅可执行真实只读准备；**尚未获得官方模拟下单授权，未发送订单**。

只读账户投影会保留供应商零价格记录和原始未知状态，以完成账户检查并展示`initial_order_gate`。它不修改执行订单的正价格校验，也不放宽新准备的空订单初始条件；只读完成不代表可以提交订单。[9月20日后续修复与实际读取](research-evidence/futu-preflight-20260920/resolution-followup.md)保留了这些边界的证据。

冻结的首个工程验收提案为：已核对的US模拟账户、`US.AMD`、BUY 1股、限价1.00美元、普通限价DAY/RTH、禁止自动调价或换意图重试。最多一次SDK提交、一次对同一订单的撤销。这个远离当前价格的限价单用于验证订单接入与撤销，不用于盈利研究；供应商可能拒绝，拒绝时保留实际结果，不改价制造成功。若意外成交，保留持仓并停止；本提案不授权额外卖出。

1美元为订单名义金额上限。3美元仅为本地预留参数，不代表真实费用或保证的总费用上限。[富途模拟交易说明](https://openapi.futunn.com/futu-api-doc/en/qa/trade.html)列明模拟成交明细/推送、订单费用和现金流水接口不支持；2026-09-20核查的在线说明为v10.11，受验SDK仍固定为10.7.6708，文档不能代替固定SDK与OpenD的实际验证。若实际模拟界面确能提供独立账单/导出原件，再经维护者核对后接纳；不存在或尚未取得时，会计保持未验证，不填零，也不把生成不存在的账单作为开发任务。没有真实资金或REAL操作权限。

## 分阶段执行

每次CLI调用都通过已有Windows Job启动一个新进程，180秒执行上限、128KiB输出上限、5秒清理预算。SDK日志及全部账户信息只存私有输出目录。阶段之间不自动续跑、不注册任务、不改变现有观察窗口。发布时先从固定Git提交导出原始字节；准备阶段把四个执行文件的摘要写入数据库，后续代码变化会停止操作。

工作进程在连接SDK前核验自己属于仍存活父进程持有的私有Windows Job，检查本次执行期限和输出上限；直接传内部工作参数不能省略此核验。回执文件在任何SDK调用前独占创建，已完成或中断的阶段目录不能复用。源码及授权在提交/撤单调用前再次检查，发现变化时保留已持久化的未知状态并停止，不自动撤回提交领取。

| 阶段 | 实际行为 | 仍不能证明什么 |
|---|---|---|
| `prepare` | 两轮真实账户读取、证券规则读取；创建新私有数据库并冻结意图，输出待授权提案 | 不生成授权、不领取提交机会 |
| `submit` | 要求单独授权文件；重新读取账户/证券/容量；持久化可能提交，再至多调用一次SDK | 返回未知不代表未提交 |
| `recover` | 新进程打开同一数据库，只查询并处理回调、保留订单身份与完整的两轮读取依据；分别报告订单路径和会计结果 | 多次读取不是原子快照；缺失费用不补零 |
| `duplicate-probe` | 在已有持久化尝试后调用既有领取逻辑，必须拒绝重复领取；不创建SDK连接 | 不测试券商去重，也不再次发送订单 |
| `cancel` | 要求同一意图授权文件；只撤销数据库绑定的订单ID，核验返回环境/订单ID并保存原响应 | 撤单响应不是终态 |
| `admit-statement` | 保存维护者提供的实际原件，校验摘要/订单/数量后复用已有账本 | 摘要不认证原件真实性；仍须再次`recover`核对实际余额和持仓 |

`submit`有意忽略同步响应的状态推进并结束进程，用于明确标记的客户端响应丢失演练；真实同步原件仍保留在私有数据库。若回调先到，其原件与订单身份照实保留，不伪称发生了供应商网络故障。下一进程先查询恢复，只有识别到对应订单后才能申请撤销。

每个输出目录必须全新，数据库保持同一物理位置。重复`prepare`不会覆盖已有数据库。跨进程账户权威继续使用已有持久登记；维护者须保证本次验收期间没有其他程序或手工操作同一模拟账户。跨机器独占不由本机锁证明。

初始账户可能已有非AMD持仓，包括较长的期权代码。这些代码和账户原始数量仅作为对账初值保留，不转换为标的股票股数，不新增可交易价格规则或处置权限；未来读取发生数量或现金差异仍会停止。首轮真实准备因原有代码长度限制停止，12次只读请求成功、SDK订单调用为零，原失败回执保留。

示意命令（占位文件均在本机，不提交账号或授权到GitHub）：

```text
python tools/futu_simulation_cycle.py prepare --profile <private-profile.json> --database <cycle.sqlite> --output-dir <new-prepare-dir>
python tools/futu_simulation_cycle.py submit --database <cycle.sqlite> --authorization <approved-private-authorization.json> --output-dir <new-submit-dir>
python tools/futu_simulation_cycle.py recover --database <cycle.sqlite> --output-dir <new-recover-dir>
python tools/futu_simulation_cycle.py duplicate-probe --database <cycle.sqlite> --output-dir <new-duplicate-dir>
python tools/futu_simulation_cycle.py cancel --database <cycle.sqlite> --authorization <approved-private-authorization.json> --output-dir <new-cancel-dir>
```

授权必须由维护者单独批准，再绑定实际账户、此意图与载荷摘要、明确到期时间以及允许的提交/撤单操作。运行时剩余有效期不得超过24小时；查询后和调用SDK前仍会重验。限价、数量、意图和源文件不能在授权后暗改。闭市、账号不符、现金不足或来源变化均停止。

## 完成标准

各阶段私有回执的 `acceptance` 分层报告，不使用一个总PASS覆盖所有能力。既有 `official_cycle_complete=false` 保留，回执不自动批准下一阶段。

| 层 | 记录与通过范围 | 不自动推导 |
|---|---|---|
| `environment_and_permission` | 本阶段模拟账户核验、固定载荷、源码是否匹配，以及真实派发前是否完成授权检查 | 只读准备不授予提交权限；历史授权检查不代表授权目前仍有效 |
| `order_transport` | 累计数据库原件中的提交派发、订单身份、供应商状态、回调、撤单ACK/终态、拒绝重复领取；本阶段查询是否再次识别同一订单 | SDK派发不等于券商受理；撤单ACK不等于撤销终态；没有总路径通过标记 |
| `account_state` | 本阶段实际现金、持仓、订单投影的两轮一致读取及时间；单列对账结果和错误 | 不是原子快照；初始锚点和提交前检查不代表订单后的余额已核算；读取一致也不能证明没有外部事件 |
| `fee_accounting` | `SUPPORTED_AND_VERIFIED` / `UNKNOWN` / `UNSUPPORTED_BY_PROVIDER`，实际费用独立于预留值 | 不用空列表、失败返回、零成交、拒单、撤单或文档费率认定实际费用为零 |
| `strategy_and_live` | 始终保留策略有效性、自主交易、REAL权限未放行；独立报告风险停止/阻断状态 | 任何接口通过都不证明盈利，也不授权新增风险或额外卖出 |

费用层的 `provider_api_status=UNSUPPORTED_BY_PROVIDER` 是明确的提供方接口限制，不是本次请求测得的费用。尚未提交、仅接纳原件但尚未再次对账、或实际对账失败时，精确会计结果为 `UNKNOWN`。已发生可能提交且没有独立原件时为 `UNSUPPORTED_BY_PROVIDER`，实际费用仍为 `null`。只有当前订单版本的独立原件已接纳，且本阶段 `recover` 的现金/持仓对账匹配，才能记录 `SUPPORTED_AND_VERIFIED`；来源仍明确为维护者核对的原件，摘要不认证真实性。

若查询已经识别订单，但费用或成交金额证据缺失，`recover` 返回 `ORDER_OBSERVATIONS_RECORDED_ACCOUNTING_UNVERIFIED` 并保留 `accounting_error`。这表示订单观察已记录；内部会计对账仍失败，原风险停止继续有效。故可以诚实报告“提交/查询/撤销终态路径已有证据，精确会计未验证”。其他错误（错账户、读取变化、未知外部订单、订单缺失、余额不符等）仍返回 `INCOMPLETE`。

初次提交前检查的是实际空订单账户锚点及当前现金/持仓；没有要求提交前提供未来订单的费用原件。提交后出现会计缺口不会开放新增风险，也不能重新发送同一意图。已绑定己方订单的撤销不以完整会计为前置，但仍要求单独有效授权、同一账户/源码/订单绑定和最多一次撤销；恢复到订单ID与会计未核实可以同时成立。

现有1美元提案只检验有限接口路径，逐项按实际结果验收：

| 实际结果 | 可以验收 | 仍未覆盖或需停止 |
|---|---|---|
| 查询/回调的绑定订单明确为 `FAILED` / `SUBMIT_FAILED` | 拒单与真实错误留存 | 不能声称受理、撤销、成交均通过 |
| SDK返回错误但没有明确订单状态，或响应丢失 | 错误/未知状态留存；后续查询恢复及不重发 | 错误返回和空订单查询都不单独证明拒单；无法恢复时保留 `UNKNOWN_NO_RESEND` |
| 订单受理，撤单ACK后新进程查询到撤销终态 | 提交、身份查询、撤销请求和终态；另核对实际回调与重复领取回执 | 未观察到的回调不能补造；未覆盖成交、部分成交或真实可成交性 |
| 意外模拟成交 | 保留实际订单状态、累计数量和风险阻断 | 不扩大处置权限；精确费用仍须独立原件；没有额外卖出或REAL权限 |

订单接口结论须可定位真实提交、查询、回调、终态、恢复与拒绝重复领取的原件；未发生的路径逐项保留未覆盖。需要可成交模拟订单或部分成交实验时，另立方案和单独授权，不能在现有提案中改价、增加次数、换意图或数量。所有账户原件和回执仍只在私有目录；本地夹具、绿色CI、一个成功返回或未发生异常均不能代替实际订单证据。
