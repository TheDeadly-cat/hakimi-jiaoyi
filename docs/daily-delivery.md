# 日常候选：版本、入口与旧记录

本轮日常候选为 `0.6.0.dev2`，仍是开发候选。已合并主分支、开发候选和正式 Release 是三种不同身份，以 [当前状态](../CURRENT_STATUS.md) 为入口核对。`v0.2.1` 不包含本候选的工作台能力。

## 打开与识别

本机交付使用独立目录中的 `Start-Workbench.cmd`。一个入口绑定一个已验收 Python 安装、候选包及明确数据工作区。首次使用和重开均从该入口进入；它不会选择原终端的默认数据目录，也不替换旧快捷方式。

打开工作台后展开版本与工作区说明，核对包版本、构建提交、构建时源码状态、实际加载的代码内容身份和数据工作区。安装包内记录的构建提交才是构建身份；后续验收文档提交不重新标注原包。版本号相同也不能代替内容身份核对。缺少构建记录时显示未知，不使用当前目录的 Git 提交冒充安装包身份。

桌面启动准备工具 `tools/prepare_workbench_desktop.py` 复用普通 wheel 验收回执，核对精确安装与已验收包，在一个全新目录生成启动入口和本机交付清单。它使用已有 Electron 程序，不是包含所有运行时的公共安装器；生成的本机绝对路径不能直接作为另一台电脑的安装入口。迁移机器时需重新安装精确依赖、验收并生成当地入口。

## 读取旧任务、账户与报告

| 现有记录 | 本候选中的处理 | 需要继续计算时 |
|---|---|---|
| 已保存普通任务与运行报告 | 按原身份读取，不重新计算，不改原报告 | 输入更新时通过“更新已有任务输入”建立新版本；新结果保留新运行身份 |
| 原连续账户，代码和依赖身份一致 | 显示当前运行兼容状态，仍受输入、时间、账本与风控检查约束 | 按原工作台流程明确操作，不因页面显示兼容而自动运行 |
| 原连续账户，代码或依赖身份不匹配 | 旧账本与结果保持可读；显示具体不兼容原因 | 使用其原安装和原工作区继续，或在新候选里用新账户开始；不直接搬移旧持仓、改签历史或续写原账本 |
| 身份缺失、损坏或无法核对的记录 | 显示未知或停止原因，不宣称可继续 | 保留原件及原安装，先核对证据；不通过重建文件掩盖缺口 |
| 原终端的结构、同行比较和指标卡片 | 仍从原终端进入，保持原计算合同 | 不将原终端结果当成正式工作台内核输出 |

读取用的数据副本保留原文件字节。副本中的历史来源路径可能指向其原存档；这不是已经完成跨机器迁移的证明。旧安装与旧工作区须成对保留。新包不会自动升级连续账户，也不会把原账户持仓迁移到新账户。

## 工程与策略证据分开看

工程验收说明：这个精确包能否安装、启动、读取旧记录、执行已覆盖流程，以及重开后是否保留数据。通过的测试数量、CI 和桌面截图只能支持对应工程范围。

策略证据说明：数据来源、实际可用时间、评估区间、交易样本、成本和基准是否足够支持研究结论。现有 NDAQ、KO 验收各只有 15 个评估交易日、1 次完整买卖、2 次成交；后续固定参数检查仍为 `NOT_RUN`。此次入口交付不新增经济运行，不改变这组证据的成熟度。

日常数据操作继续使用 [已有流程](daily-workbench.md)：逐只检查 → 审阅修订 → 明确冻结 → 新任务版本 → 查看诊断与成本验证。跨年日历、公司行为扩展、前瞻验证约定属于后续工作；当前停止原因和历史可用性检查继续有效。

## 保全与回退

新候选使用新安装目录与明确数据工作区。旧启动器、旧包、旧工作区和历史验收回执不覆盖。需要回看旧账户时，关闭当前候选窗口后，打开该账户原来的启动器；不同候选的程序与数据路径必须保持各自对应。

本轮不合并 PR、不发布 Release、不连接券商、不启动模型讨论或付费 Provider、不迁移研究侧数据库。
