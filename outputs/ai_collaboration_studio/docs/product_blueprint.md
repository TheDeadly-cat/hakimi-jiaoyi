# AI 共创室：产品大纲 v0.1

## 1. 产品定义

AI 共创室不是“把多个聊天机器人摆在一起”，而是一个可编排、可追踪、可积累的协作空间：

> 用户创建一个房间，定义目标和规则，为 AI 成员赋予身份；用户与成员在群聊中讨论，成员能够阅读上下文、回应彼此、提出反证、分工研究，并把过程沉淀为结论、待办和可继续编辑的产物。

股票研究、体育研究、项目可行性、方案撰写只是场景模板，不是产品边界。

## 2. 四个核心原则

1. **身份高于模型**：用户看到的是“战略主持人、反方审查员、事实研究员”，模型只是身份背后的执行器。
2. **对话高于报告**：观点必须出现在连续群聊里，后发言者需要读取并回应前序观点。
3. **证据高于气氛**：重要结论必须能追溯到发言、材料或用户输入；不把一致意见伪装成事实。
4. **产物高于热闹**：每个房间最终要形成结论、分歧、待办和可导出的文档，而不是无限闲聊。

## 3. 核心对象

### 房间 Room

- 标题、目标、场景模板、房间规则。
- 成员、共享材料、消息、讨论轮次、结论与待办。
- 可长期存在，不因一次模型请求结束。

### 成员 Member

- 显示名：例如“反方审查员”。
- 身份说明：它是谁、负责什么、不负责什么。
- 发言风格：简洁、严谨、创意、挑错等。
- 模型适配器和模型名。
- 是否参与当前轮次、发言顺序和权限。

### 讨论轮次 Round

- 本轮目标。
- 参与成员和发言顺序。
- 前序记录、暂停/继续/停止状态。
- 每位成员的开始、完成、失败和耗时事件。

### 消息 Message

- 用户消息、AI 消息、系统事件。
- 发言者、回复对象、轮次、时间和模型来源。
- 后续支持引用、编辑分支和重新生成。

### 共享材料 Context

- 粘贴文本、文件、链接、结构化数据和工具结果。
- 每份材料保留来源、更新时间和可见范围。

### 产物 Artifact

- 会议纪要、方案、研究简报、决策记录、任务清单。
- 由用户确认后进入正式版本；AI 草稿不得自动覆盖用户版本。

## 4. 主要工作流

1. 新建房间并填写本轮目标。
2. 从身份模板选择成员，或自行定义身份。
3. 添加共享材料。
4. 用户在群聊中发言，或点击“开始一轮”。
5. 编排器按顺序唤醒成员；每位成员读取房间目标、材料和前序发言。
6. 成员必须明确赞同、补充或质疑谁，并给出下一步。
7. 用户随时插话、暂停、调整身份或改变顺序。
8. 系统从对话中整理结论、分歧和待办，由用户确认。

## 5. 场景模板

- **开放共创**：主持人、创意提出者、反方审查员、落地设计师。
- **项目研究**：研究负责人、事实研究员、商业审查员、方案架构师。
- **方案撰写**：结构编辑、内容作者、读者代表、质量审校。
- **体育研究**：数据研究员、战术观察员、风险审查员、信息核验员。只做研究，不代替用户投注或执行资金动作。
- **市场研究**：趋势研究员、基本面研究员、反方审查员、风险记录员。只做研究，不执行交易。

## 6. 技术架构

```text
React Client
  -> Room API / NDJSON Round Stream
  -> Discussion Orchestrator
       -> Identity Prompt Builder
       -> Context Window Builder
       -> Provider Registry
            -> OpenAI Adapter
            -> DeepSeek Adapter (next)
            -> Ark / Doubao Adapter (next)
            -> Other Provider Adapter
  -> SQLite Store
       -> rooms / members / messages / rounds / artifacts
```

关键边界：

- 编排器只依赖统一 `Provider` 接口，不知道厂商 API 细节。
- 身份提示词属于成员，领域模板属于房间，两者不能写死在模型适配器中。
- 前端只接收 provider、model、状态等安全元数据，永远不接收密钥。
- 高风险外部动作必须由未来独立工具权限层处理；第一阶段完全不提供执行工具。

## 7. 路线图

### Phase 1：能讨论

- 房间、成员身份、连续群聊、顺序发言、SQLite、OpenAI 适配器。
- 用户可随时插话并开始下一轮。

### Phase 2：能共创

- 共享文件和链接、引用证据、身份模板、动态发言顺序。
- 主持人根据分歧决定追问谁，而不只是固定轮询。

### Phase 3：能产出

- 结论/分歧/待办自动整理。
- 文档工作区、版本对比、用户确认和导出。

### Phase 4：能扩展

- 插件化模型与工具、语音房间、团队协作、权限与成本预算。
- 领域包只提供模板、资料连接器和评价标准，不污染核心聊天架构。

## 8. 第一阶段验收标准

- 新建房间后无需刷新即可进入。
- 至少三个不同身份能按顺序发言。
- 后发言者能点名前序成员并回应其观点。
- 用户消息和 AI 消息在同一时间线中显示。
- 刷新页面后房间、身份和消息仍存在。
- 模型失败只影响当前成员，不中断整个房间。
- 密钥不进入前端、日志、SQLite 或版本库。
