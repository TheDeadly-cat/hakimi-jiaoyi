# ADR0481: Replay cursor provider conformance transcript content verification v1

## Status

Accepted as an unmounted, synthetic, research-only local content verifier. It does not read filesystem artifacts, logs, runtime state, caches, databases, credentials, or network resources. It does not call a provider or authorize current, runtime, paper, live, writer, execution, profitability, or trading activity.

## Context

ADR0480 makes each signed observer case hash commit to a complete transcript descriptor and requires exact manifests for every passing observer. It intentionally does not receive the referenced bytes. A manifest can therefore reach local structural `PASS` while all artifact-retrieval facts remain false.

The existing ADR0113 transparency/availability evaluator was audited for reuse. It is tightly bound to ADR0112 provider-identity receipts, nine specialized roles, and artifact-specific transparency-log domains. Reusing it for replay-cursor transcripts would create a false cross-domain alias; copying its log and dual-observer protocol would create a parallel authority boundary.

## Decision

Add a narrower local-only consumer:

- one exact content bundle per ADR0480 passing observer;
- exactly 19 cases in preregistered order;
- five canonical `base64url-no-padding` components per case: transcript artifact, command trace, result trace, stdout, and stderr;
- SHA-256 equality against every ADR0480 manifest field;
- a 1 MiB per-component bound and 16 MiB per-observer bundle bound;
- aggregate evidence requiring the exact ADR0480 binding and an exact content bundle for every bound observer.

The sealed content bundle necessarily contains caller-supplied synthetic bytes in encoded form so it can be exactly rebuilt. Aggregate public evidence contains only bundle hashes, observer IDs, counts, and byte totals. It never projects payload content.

## Consumer-first activation order

1. ADR0479 exact observer quorum.
2. ADR0480 exact signed-report to transcript-manifest binding.
3. ADR0481 local payload hash and size verification.
4. Independently authorized artifact publication, retrieval, transparency, persistence, runner/environment provenance, and observer execution source adapters.
5. Authorized external provider endpoint and real conformance execution.
6. Separately reviewed and explicitly authorized current transition.

ADR0481 completes step 3 only. It is not mounted into `current`.

## Adversarial matrix

- ADR0480 hash-only binding with no content bundles: retrieval remains unverified;
- missing, duplicate, or unbound observer bundle: aggregate blocked;
- missing/reordered case or wrong shape: bundle rejected;
- padded/noncanonical base64url: rejected;
- changed content with a valid encoding: rejected by manifest hash mismatch;
- wrong manifest hash: rejected;
- component above the byte limit: rejected before hash promotion;
- changed ADR0480 evidence: exact upstream verifier blocks content evidence;
- resealed bundle or aggregate permission promotion: exact rebuild verifiers reject it;
- reversed bundle order: deterministic aggregate evidence is unchanged;
- complete matching synthetic bytes: local hash/size verification passes while external retrieval, public availability, persistence, source truth, provider conformance, and authority remain blocked.

## Consequences and limits

ADR0481 proves only that bytes supplied directly to the local function match ADR0480's committed hashes and size limits. It does not prove those bytes were published, independently retrieved, durable, externally visible, produced by the claimed runner/environment, or generated by real observer/provider execution. It does not prove provider conformance, profitability, paper, live, or trading permission.

The natural-forward chain remains `audit-v2/readiness-v3 -> maturity-v3/dashboard-v7 -> pack-v6/evidence-v2 -> snapshot-v4/summary-v2`. Legacy pack-v5 public reads remain `UNKNOWN`; pointer-v2 is unchanged and is not reissued.
