# ADR 0490: Identity-bound signed provider transcript content bridge candidate v1

## Status

Accepted as an unmounted, synthetic-only candidate. It is not a current consumer and does not authorize provider activation, cursor writes, paper execution, or live execution.

## Context

ADR 0489 binds canonical proposal identity and a signed provider receipt to the local observer quorum. ADR 0480 already defines the complete transcript descriptor preimage for every signed case evidence hash. ADR 0481 already verifies caller-supplied transcript, command trace, result trace, stdout, and stderr bytes against those descriptors under strict encoding and size bounds.

The remaining gap is consumer identity. The existing ADR 0480/0481 fixtures bind their own receipt and quorum. Their manifests, bundles, and aggregate evidence cannot be spliced onto ADR 0489. Every signed report, manifest, bundle, binding document, and content evidence document must be rebuilt against the exact ADR 0489 receipt and quorum.

## Decision

Add a narrow bridge requiring both sides to reconstruct exactly:

1. The ADR 0489 identity-bound signed provider conformance bridge.
2. The ADR 0481 transcript content verification evidence and its ADR 0480 binding context.

The bridge requires exact equality across the shared quorum evidence, signed reports, conformance plan, provider preregistration, and signed receipt evidence. It pins the ADR 0489 hash, ADR 0481 hash, ADR 0480 hash, quorum hash, receipt evidence hash, plan hash, provider preregistration hash, replay-cursor CAS hash, and provider command hash.

The public bridge output contains only bounded counts, metadata, and hashes. Raw payloads, content bundles, manifests, case descriptors, observer reports, receipt documents, cursor objects, keys, and signatures are not projected.

## Evidence semantics

A passing result proves only that bytes supplied directly to the local verifier match the transcript descriptor hashes and size limits already committed by local observer signatures. It does not prove that the artifacts were published, independently retrieved, durable, externally visible, produced by the claimed runner or environment, or generated by real observer/provider execution.

It therefore does not prove endpoint identity, provider-issued provenance, provider conformance, atomicity, durability, linearizability, restart recovery, rollback resistance, profitability, or trading authority.

## Authority boundary

The neutral decision path remains:

`SOURCE -> GAP -> MATURITY -> PERMISSION`

The final permission state remains `BLOCKED`. Runtime mounting, current admission, provider activation, paper authority, live authority, and profitability proof remain false.

## Consumer-first activation order

1. Keep ADR 0490 unmounted and validate it with pure synthetic fixtures.
2. Add a separately versioned external artifact publication and retrieval receipt.
3. Bind runner implementation provenance and environment manifest provenance.
4. Add provider endpoint identity and provider-issued execution attestation.
5. Add restart and rollback-resistance evidence without granting cursor-write authority.
6. Collect natural-forward evidence under the existing single-look chain.
7. Consider a current switch only after separate authorization and complete acceptance evidence.

No step automatically activates the next step. No pointer is reissued by this ADR.
