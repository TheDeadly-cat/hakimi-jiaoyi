# 哈基米交易 v2 产品主线：行情工作台 + 可靠量化内核

更新时间：2026-07-09

## 产品目标

哈基米交易 v2 从“好看的交易终端”升级为“行情分析、市场异动捕捉、策略研究和模拟验证工作台”。默认路径永远是研究和模拟盘；实盘真实下单继续保持硬保护墙。

## 1. TradingView：行情体验成为主工作流

- 首页只保留关键盯盘内容：标的、K线、盘口、逐笔、策略状态、风险状态。
- 命令面板要能执行动作：搜标的、刷新数据、跑回测、打开风险解释、停止策略。
- K线上直接显示策略锚点：买入理由、不买理由、止盈止损、反证条件。
- 增加回放模式，用历史行情复盘策略信号和模拟订单。

## 2. NautilusTrader：后端拆成交易内核

- `market_data_service.py`：统一 OKX、Futu、本地缓存、CSV，所有数据携带来源、新鲜度、实时状态、降级原因。
- `risk_service.py`：所有人工单、策略单、条件单、守护进程先走风控。
- `paper_executor.py`：模拟成交、手续费、滑点、IOC/FOK/Post Only、订单生命周期。
- `audit_log.py`：统一事件审计，当前兼容 JSONL，后续升级 SQLite。
- `event_bus.py`：行情、信号、风控、订单、AI 审查统一成为事件流。

## 3. Freqtrade：模拟盘和策略体检做扎实

- 默认永远是模拟盘，实盘继续硬锁。
- 策略启动前必须经过回测、手续费/滑点检查、最大回撤检查、未来函数检查。
- 策略体检需要识别偷看未来 K 线、样本太少、过拟合、手续费敏感。
- 每笔模拟单必须显示触发原因、风控结果、成交模型和审计记录。

## 4. OpenBB：数据层接一次，多处消费

- 同一个标的只拉一次行情。
- 前端、AI、策略、回测消费同一份标准化快照。
- 每个数据点显示来源、延迟、缓存年龄、失败原因。
- Futu 离线时明确标注“本地旧缓存”，不能误导成实时数据。

## 5. Hummingbot：交易所适配插件化

- 新增 adapter 边界：`okx_adapter`、`futu_adapter`、`stock_cache_adapter`、`csv_adapter`。
- 策略和 UI 只依赖统一数据/执行接口，不直接依赖具体交易所实现。
- 后续新增交易所或数据源时，不改策略层和主界面。

## 6. QuantConnect LEAN：研究到发布流水线

主流程调整为：

研究驾驶舱 -> 策略实验室 -> 回测/寻优 -> 策略体检 -> 模拟运行 -> 审计报告

这条链路优先级高于“点一个按钮启动策略”。
