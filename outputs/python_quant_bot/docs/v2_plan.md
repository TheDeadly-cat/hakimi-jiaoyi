# 哈基米交易 v2 Plan

V2 的目标不是继续堆交易按钮，而是把当前本地交易终端升级为可审计、可拆分、可守护的量化平台内核。

## 当前版本

```text
2.0.0-alpha
```

## V2 核心原则

- 实盘默认继续阻断，直到独立风控、执行审计、API 权限和急停链路全部完成。
- 页面服务只负责展示、配置和本地控制，不应长期承载全部交易内核。
- 策略、数据、风控、执行、AI 研究要逐步拆成独立服务或独立模块。
- DeepSeek 可以生成草稿和解释，但不能自动应用补丁，不能接触密钥，不能下单。

## 第一批已落地

- `/api/platform/v2`: v2 平台状态、健康评分、模块成熟度、路线图。
- 系统区「哈基米交易 v2 控制中心」：展示版本、健康评分、实盘硬墙、高风险模块、建设路线。
- Code Worker 草稿队列：DeepSeek 只产出草稿，Codex 审查后再应用。
- `exchange_terminal/services/risk_service.py`: 第一块拆出的 v2 服务，负责风控快照和下单前检查。

## 下一批拆分顺序

1. `risk_service.py`
   - 统一实盘硬墙、影子风控、急停、熔断、仓位限制。
   - 所有人工/策略/条件单执行路径必须先经过它。

2. `paper_executor.py`
   - 统一模拟成交、盘口撮合、滑点、手续费、资金费率、订单生命周期。
   - 后续真实执行器必须和模拟执行器共享订单模型。

3. `market_data_service.py`
   - 统一实时行情、历史 K 线、本地缓存、数据延迟状态。
   - 后续支持 OKX、富途、CSV、本地数据库多源切换。

4. `strategy_service.py`
   - 统一策略注册、参数、评分、回测、寻优、策略日志。
   - 输出「为什么买、为什么不买、为什么卖」。

5. `ai_research_service.py`
   - 统一 DeepSeek 分析、机会扫描、Code Worker 草稿、AI 审计日志。
   - 所有 AI 建议必须附带行情快照和风险边界。

## V2 完成标准

- 风控和执行从单体后端中拆出。
- 模拟执行使用事件驱动队列。
- 市场数据可追踪来源、延迟和缓存状态。
- 策略实验室可以对同一币种多策略并行观察。
- 实盘仍默认关闭；若未来开启，需要单独授权页、只读/交易权限检查、急停和审计日志。
