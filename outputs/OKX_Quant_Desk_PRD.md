# OKX Quant Desk 产品需求文档

版本：v0.1  
日期：2026-06-15  
定位：面向新手的 OKX 量化交易工作台

## 1. 产品愿景

OKX Quant Desk 是一款面向新手和半自动交易者的量化交易软件。它不以“承诺收益”为卖点，而是帮助用户用更可理解、更可控、更可复盘的方式接触 OKX 量化交易。

核心路径：

```text
连接 OKX -> 学习策略 -> 回测验证 -> 模拟盘运行 -> 小资金实盘 -> 风控复盘
```

产品第一原则：

- 默认安全，不默认激进。
- 默认模拟盘，不默认实盘。
- 默认低杠杆或无杠杆，不默认高风险。
- 所有交易动作都必须可解释、可暂停、可追踪。

## 2. 目标用户

### 2.1 纯新手

特征：

- 会使用交易所，但不了解量化。
- 不知道 API Key、回测、止损、网格、均线等概念。
- 容易被高收益策略吸引，风险意识较弱。

核心需求：

- 按步骤配置。
- 系统解释参数含义。
- 先模拟，后实盘。
- 有明确风险提示。

### 2.2 半自动交易者

特征：

- 有自己的交易想法。
- 不想一直盯盘。
- 可能懂一点指标，但不会写程序。

核心需求：

- 用策略模板快速搭建交易逻辑。
- 能看回测结果。
- 能设置通知和风控。

### 2.3 进阶量化用户

特征：

- 熟悉指标、策略、回测。
- 可能希望写 Python 策略。

核心需求：

- 自定义策略。
- 参数优化。
- 多策略组合。
- 更完整的数据导出和日志。

第一版优先服务前两类用户。

## 3. 产品范围

### 3.1 MVP 必做

MVP 目标是跑通 OKX 量化闭环：

1. OKX API 连接。
2. 账户余额读取。
3. 行情数据读取。
4. 策略模板选择。
5. 均线策略。
6. 网格策略。
7. 历史回测。
8. 模拟盘运行。
9. 小额实盘交易。
10. 止损、止盈、仓位限制。
11. 一键暂停全部策略。
12. 交易记录和简单复盘。

### 3.2 MVP 暂不做

- 社区跟单。
- 策略 marketplace。
- 高频交易。
- 复杂套利。
- 跨交易所交易。
- AI 自动生成实盘策略。
- 手机 App 原生版。

这些功能容易增加合规、风控和技术复杂度，不适合第一版。

## 4. 核心用户流程

### 4.1 新手首次使用流程

```text
欢迎页
-> 选择经验水平
-> 查看风险说明
-> 连接 OKX API
-> 默认进入模拟盘
-> 选择策略模板
-> 设置交易对和资金比例
-> 一键回测
-> 查看回测报告
-> 启动模拟盘
-> 达到模拟盘观察期后提示是否进入小额实盘
```

### 4.2 策略上线流程

```text
选择策略
-> 填写参数
-> 风险预览
-> 回测
-> 模拟盘
-> 启动实盘
-> 运行监控
-> 复盘报告
```

### 4.3 异常处理流程

```text
检测异常
-> 暂停相关策略
-> 保留当前持仓或按预设规则处理
-> 通知用户
-> 记录异常日志
-> 等待用户确认或自动恢复
```

## 5. 页面规划

### 5.1 首页仪表盘

用途：让新手一眼知道当前是否安全。

核心模块：

- 当前模式：模拟盘 / 实盘。
- 账户总权益。
- 今日盈亏。
- 当前持仓。
- 正在运行的策略。
- 风险等级。
- 最近交易。
- 一键暂停全部策略。

首页不堆复杂图表，优先回答三个问题：

1. 我现在有没有在交易？
2. 我现在亏了还是赚了？
3. 有没有风险需要马上处理？

### 5.2 账户连接页

核心功能：

- 输入 API Key、Secret Key、Passphrase。
- 连接测试。
- 权限检测。
- IP 白名单提醒。
- 模拟盘连接说明。

安全提示：

- 不建议开启提现权限。
- 新手默认使用模拟盘。
- 实盘前必须确认风险提示。

### 5.3 策略模板页

每个策略卡片显示：

- 策略名称。
- 适合行情。
- 风险等级。
- 推荐交易品种。
- 推荐资金占比。
- 是否适合新手。
- 查看详情。

第一版策略：

1. 均线趋势策略。
2. 现货网格策略。
3. 定投策略。
4. RSI 反转策略。

MVP 可先实现均线趋势和现货网格。

### 5.4 策略配置页

新手模式字段：

- 交易对。
- 使用资金比例。
- 止损比例。
- 止盈比例。
- 每日最大亏损。
- 是否开启模拟盘。

高级模式字段：

- K 线周期。
- 指标参数。
- 最大持仓数量。
- 下单类型。
- 滑点假设。
- 手续费假设。

每个参数旁边提供短解释。例如：

```text
止损比例：当亏损达到这个比例时，系统会自动退出，防止亏损继续扩大。
```

### 5.5 回测中心

输入：

- 交易对。
- 时间范围。
- 策略。
- 参数。
- 初始资金。
- 手续费。
- 滑点。

输出：

- 总收益率。
- 最大回撤。
- 胜率。
- 交易次数。
- 盈亏比。
- 最大连续亏损次数。
- 手续费影响。
- 净值曲线。
- 交易点位图。

新手解释：

- 收益率高但回撤大，要标为高风险。
- 交易次数太多，要提示手续费风险。
- 回测时间太短，要提示结果不可靠。

### 5.6 模拟盘页

核心功能：

- 模拟资金。
- 模拟持仓。
- 模拟订单。
- 模拟盈亏。
- 与实盘行情同步。
- 模拟盘运行天数统计。

新手保护：

- 默认至少运行 7 天后再建议实盘。
- 如果模拟盘亏损超过阈值，不建议进入实盘。
- 如果策略交易次数太少，提示观察时间不足。

### 5.7 实盘监控页

核心功能：

- 实盘策略列表。
- 当前持仓。
- 当前订单。
- 实时盈亏。
- 风控状态。
- 手动暂停。
- 手动平仓。

危险操作必须二次确认：

- 开启实盘。
- 提高资金比例。
- 提高杠杆。
- 关闭止损。
- 手动平仓。

### 5.8 风控中心

必备设置：

- 单笔最大亏损。
- 单日最大亏损。
- 单策略最大资金占比。
- 总账户最大资金占比。
- 连续亏损暂停。
- 异常波动暂停。
- API 异常暂停。
- 一键暂停全部策略。

默认建议：

- 新手模式：单策略最多使用 10% 账户资金。
- 新手模式：优先现货。
- 合约模式：默认 1x，最高需要用户主动解锁。
- 每日亏损达到 3%-5% 后自动暂停。

### 5.9 交易记录与复盘页

每笔交易记录：

- 时间。
- 交易对。
- 策略。
- 买入/卖出方向。
- 价格。
- 数量。
- 手续费。
- 盈亏。
- 触发原因。
- 当时指标状态。

复盘报告：

- 今日总盈亏。
- 今日最大亏损。
- 哪个策略贡献最大。
- 哪个策略亏损最大。
- 是否触发风控。
- 明日建议：继续观察 / 降低仓位 / 暂停策略。

## 6. 策略设计

### 6.1 均线趋势策略

适合：

- 趋势行情。
- BTC、ETH 等流动性较好的品种。

基础逻辑：

```text
如果短期均线上穿长期均线，并且当前没有持仓，则买入。
如果短期均线下穿长期均线，或者触发止损，则卖出。
```

默认参数：

- 短期均线：20。
- 长期均线：60。
- K 线周期：1h 或 4h。
- 使用资金：10%。
- 止损：3%。
- 止盈：可选，默认关闭或使用跟踪止盈。

风险：

- 震荡行情容易反复亏损。
- 信号滞后，无法买在最低点。

### 6.2 现货网格策略

适合：

- 震荡行情。
- 不适合单边暴跌行情。

基础逻辑：

```text
在设定价格区间内，将资金拆成多份。
价格下跌时分批买入，价格上涨时分批卖出。
```

默认参数：

- 网格上限。
- 网格下限。
- 网格数量。
- 投入资金。
- 单格收益目标。
- 跌破下限暂停。

新手保护：

- 必须提示“价格跌破网格下限后可能长期浮亏”。
- 默认不使用杠杆。

### 6.3 定投策略

适合：

- 长期配置 BTC、ETH。
- 不想择时的新手。

基础逻辑：

```text
按固定时间、固定金额买入。
```

默认参数：

- 周期：每日 / 每周。
- 金额：固定 USDT。
- 交易对：BTC-USDT / ETH-USDT。

### 6.4 RSI 反转策略

适合：

- 短周期超买超卖。
- 需要严格止损。

基础逻辑：

```text
RSI 低于阈值时尝试买入。
RSI 高于阈值时尝试卖出。
```

风险：

- 单边下跌中可能越跌越买。
- 必须搭配止损和仓位限制。

## 7. 风控规则

### 7.1 全局风控

- 全账户最大资金使用比例。
- 单日最大亏损。
- 连续亏损暂停。
- 极端波动暂停。
- API 连接异常暂停。
- WebSocket 行情延迟暂停。
- 数据缺失暂停。

### 7.2 策略风控

- 单策略最大资金比例。
- 单策略最大持仓数量。
- 单策略最大亏损。
- 单策略最大连续亏损次数。
- 单策略最大订单频率。

### 7.3 订单风控

- 下单前检查余额。
- 下单前检查最小下单量。
- 下单前检查价格偏离。
- 禁止重复下单。
- 下单失败自动重试次数限制。
- 撤单失败报警。

### 7.4 新手保护开关

默认开启：

- 模拟盘优先。
- 禁止提现权限提示。
- 单策略资金上限。
- 合约杠杆限制。
- 回测不足提示。
- 关闭止损二次确认。

## 8. 技术架构

### 8.1 推荐技术栈

前端：

- React 或 Next.js。
- TypeScript。
- TradingView Lightweight Charts。

后端：

- Python FastAPI。
- Python 交易引擎。
- PostgreSQL。
- Redis。
- Celery 或 APScheduler。

数据和计算：

- pandas。
- numpy。
- TA-Lib 或 pandas-ta。
- backtesting.py、vectorbt 或自研轻量回测框架。

交易连接：

- OKX REST API。
- OKX WebSocket。

部署形态：

- 第一版建议本地桌面或私有服务器部署。
- 后续再做云端多用户 SaaS。

### 8.2 模块划分

```text
frontend
├─ dashboard
├─ account
├─ strategy
├─ backtest
├─ paper-trading
├─ live-trading
├─ risk
└─ review

backend
├─ api
├─ okx_connector
├─ market_data
├─ strategy_engine
├─ backtest_engine
├─ paper_trading_engine
├─ live_trading_engine
├─ risk_engine
├─ notification
└─ database
```

### 8.3 关键后台服务

1. 行情服务  
   负责订阅和缓存 K 线、ticker、深度、成交。

2. 策略服务  
   负责按周期计算信号。

3. 回测服务  
   负责读取历史行情并输出回测报告。

4. 模拟盘服务  
   使用真实行情和虚拟资金模拟成交。

5. 实盘服务  
   负责下单、撤单、持仓同步、订单状态同步。

6. 风控服务  
   所有下单动作必须先经过风控服务。

7. 通知服务  
   负责 Telegram、邮件、企业微信等通知。

```text
建议只开启读取和交易权限，不要开启提现权限。
```

### 11.2 模拟盘提示


```text

```

```text

```

## 14. 关键风险

### 14.1 交易风险

量化策略不保证盈利。必须在产品中明确提示风险，并且默认使用模拟盘。

### 14.2 技术风险

- API 延迟。
- WebSocket 断线。
- 订单状态不同步。
- 重复下单。
- 行情数据缺失。

处理方式：

- 所有订单幂等处理。
- 所有交易动作写日志。
- WebSocket 断线自动重连。
- 数据缺失时暂停策略。
- 下单前检查当前策略状态。

### 14.3 安全风险

- API Key 泄露。
- 用户误开提现权限。
- 服务器被攻击。

处理方式：

- API Key 加密存储。
- 不要求提现权限。
- 支持本地部署。
- 敏感操作二次确认。
- 后续支持硬件密钥或系统密钥环。

### 14.4 合规风险

不要宣传稳赚，不做收益承诺，不做代客理财表达。产品定位应是工具软件，用户自行配置和承担风险。

建议下一步进入“产品原型 + 技术骨架”阶段：

1. 画出 7 个核心页面线框图。
